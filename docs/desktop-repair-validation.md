# 桌面兼容修复验证（2026-10-31）

本轮在隔离目录、随机 loopback 端口中验证，用户的主配置保持官方直连。主 qpool 服务、LaunchAgent 与桌面接入均未重新启用。

## 修复

- 原生 `codex-auto-review` 使用原登录订阅账号、原模型与原输入；不进入任务复杂度分类，不切账号，不伪造审批结果。审批请求回执与普通会话分开，避免抢先污染普通会话绑定。模型须在原账号上游目录存在，使用前后均重新校验原账号认证。隐藏模型继续不向普通模型选择器暴露。
- 普通 qpool 会话也保存账号、模型与路由指纹；后台恢复原授权路由时可恢复同账号工具续轮。显式重新启用路由会撤销旧的普通绑定；路由变更、删除账号或模型时拒绝继续，避免自动换账号。已有旧回执但没有可信持久绑定的记录仍拒绝猜测恢复。原生入口与专用入口双向隔离。
- 恢复桌面配置前先通过 Codex 官方 `thread/list` / `thread/resume` 恢复相关聊天，包含归档、分页与各 sourceKinds；使用引擎自身的活动索引，避免旧版本 SQLite 文件干扰。原历史和元数据先备份。仍有依赖、协议失败或原提供方不是官方 OpenAI 时保留提供方设置，避免删掉后聊天无法加载。

## 实际验证

1. 隔离 qpool 控制台导入现有账号的凭据引用，主配置不变。桌面自带引擎 0.166.0-alpha.5.1 临时连接该端口，使用自动审批执行一次只读 `pwd`。账本依次记录 `gpt-6.1-sol`、`codex-auto-review`、`gpt-6.1-sol`，全部 completed。没有切到 API。验证结束销毁临时服务和目录。
2. 使用临时 CODEX_HOME、合成历史和不可达的模拟上游验证聊天恢复，不调用模型。原聊天 ID 与历史保持，官方恢复后新引擎无临时覆盖读回 openai / gpt-6.1-sol。该用例已加入 `tests/test_codex_recovery.py`，本机有对应桌面引擎时执行，其他环境显式跳过。
3. 本地 HTTP 测试覆盖隐藏审批模型透传、普通会话服务重启后继续、路由变更撤权，以及恢复失败保留配置。
4. 完整回归 162 项通过（74.048 秒）；随后恢复子进程管道关闭的定向回归 22 项通过，另增跨入口身份边界用例单独通过。Python 编译、前端语法及 diff 空白检查通过。独立审查覆盖账号隔离、路由指纹、归档/分页/各来源线程恢复、旧数据库隔离及失败保留配置。
5. 结束检查：主配置官方直连，8765 无监听，qpool LaunchAgent 数为零，聊天索引中 qpool 提供方数为零。
