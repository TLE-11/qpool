# 重新启用路由与 Plus 优先修复（2026-10-31）

## 问题与修复

`Native.enable()` 原先无条件删除 `session_bindings`，但保留请求历史。重新启用后，
专用入口看到“有历史、无绑定”，就拒绝继续，返回绑定失效的 502。该错误同样影响新建且
一直使用 qpool 的聊天，不是旧聊天或用户使用错误。

- 同一方案重复启用保持授权和绑定；保存内容未变的方案不再停用入口。
- 切换或修改方案不再删除绑定；不匹配的方案指纹仍拒绝继续，恢复原方案可续聊。
- 显式停用仍撤销入口，旧令牌不可用；重新启用原方案可读取持久化绑定。
- 自动选择先比较订阅/API，再比较账号顺序，最后比较模型组。Plus 常规不可用但
  Plus 主力可用时，不再抢先使用 Pro 常规。API 仍需明确许可，额度未知仍阻止付费回退。
- 会话页面单独显示账号策略，区分原生聊天固定账号、原生审批和首次自动选账号。
