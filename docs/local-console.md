## 启动与使用

依赖本机 `codex`；订阅账号还需要 `CLIProxyAPI`（或 `cliproxyapi`），官方 API 直接连接 `api.openai.com`。本次验证版本为 Codex CLI **0.163.0**、CLIProxyAPI **7.3.10**；Codex 专用入口使用 `--no-daemon`，其他版本需要验证参数兼容。前端无构建依赖；桌面配置编辑使用 `tomlkit>=0.13,<1` 保留原 TOML 注释和其他设置，安装 qpool 时会一并安装。

```bash
python3 -m qp web --port 8765
```

打开 `http://127.0.0.1:8765`：

1. **账号与模型 → 接入账号**：发现本机 Codex 登录，点击接入。系统读取真实订阅窗口并启动隔离适配器，加载适配器目录与原 Codex 能力目录都存在的模型。若没有登录，点击“登录另一个账号”，在 Codex 打开的官方浏览器页面完成登录，再点击重新发现。登录会使用 qpool 独立目录，不覆盖原登录。
2. **路由方案 → 新建路由**：默认选择“模型判断 · HiRoute”。选择常规、主力两组，然后从已接入的账号中选择决策模型（可与执行模型不同）、简单概率门槛及最长等待时间。可选任务分工规则：开发／方案／代码 Review 走主力组，测试执行、测试框架设计和复杂失败分析走常规组。展开“用一条任务测试真实判断”可先看分组、耗时和用量，再点击“保存并启用”。也可选固定主力组、本地规则或外部 HiRoute 决策服务。同组按页面列出的顺序使用可用账号；没有可用候选就失败，不转到按量计费渠道。
3. **Agent 接入**：选择方案并启用路由。macOS 可点击“接入 Codex 桌面端”，自动备份并设置用户级转发入口，重启桌面应用后生效；原 `openai` 聊天保留提供方身份。也可填写项目目录点击“打开 Codex”使用系统终端中的原 CLI，或复制专用启动命令。仅使用 CLI 专用入口时不修改主配置。
4. **会话与用量**：原 Codex 的每次模型请求自动产生执行记录；“决策模型记录”单独显示页面测试及实际路由的分组、概率、门槛、账号、模型、耗时和 Token。决策与执行通过记录 ID 关联，避免混淆两次调用的用量。页面不保存提示词和生成内容，不推算费用。

模型目录只证明适配器认识该模型；模型是否有账号权限最终由上游请求确认。目录不匹配时不会让 Codex 靠未知模型默认能力运行。登录文件发生身份变化时会拒绝复用旧账号；在独立目录重新登录同一账号后，页面支持“重新关联此登录”，保留账号和路由 ID。

### Codex 原生与 qpool 双向切换

Agent 接入页的“接入常驻入口”保留 OpenAI 提供方和 Codex 中选择的真实模型，只设置本地请求入口。首次接入需要重新加载 Codex；此后点击“使用原生”或“使用 qpool”，同一聊天的下一次用户提问就使用新模式，不修改 Codex 配置、不重启应用、不复制聊天。

- 原生模式使用当前 Codex OAuth 登录和原生所选模型，转发到固定官方地址，不选择其他账号，不经过 CPA 适配器。qpool 模式使用已启用的路由和原有计费许可。
- 两种模式都依赖本地后台；关闭浏览器不影响使用。停用 qpool 路由后仍可选择原生模式。
- 每轮使用 Codex 的 `client_metadata.turn_id` 固定模式。当前回复、工具回传、重试和压缩沿用原模式，点击按钮只影响下一轮。手动压缩不会抢占用户轮次绑定。缺少可靠轮次标识时拒绝猜测；本机已验证引擎为 `0.166.0-alpha.6`。
- 审批模型 `codex-auto-review` 始终走原生账号和模型，不参与自动路由。原生登录身份变化时不会把已有聊天自动迁移到另一身份。
- 原生所选模型与路由模型必须兼容：工具协议、输入类型、推理档位和上下文窗口会校验。不兼容时明确拒绝请求，不降低能力或悄悄改模型；例如原生模型窗口比目标更大时，需要选择兼容的原生模型。
- “彻底断开（需重启）”是撤销本地入口和启动项，与日常模式切换不同。原始配置保存在 `native/codex-config.before-desktop.toml`，后来修改的模型等非托管设置会保留。

曾经通过旧版 `/legacy/v1` 使用 qpool 的 OpenAI 聊天，可以升级到常驻入口后继续双向切换。升级时先核对当前原生登录与旧绑定账号一致，再复用原账号和路由绑定；不会清空旧绑定或重新挑选账号。错误账号的首次请求不会留下新绑定，恢复原账号后可重试。 此升级路径已通过隔离 HTTP 回归，覆盖双向切换、工具/压缩续轮、持久绑定重载、错误账号恢复及路由隔离；修复前复现 502，修复后全量 197 项通过，独立复核通过。本次未调用真实模型。 随后通过 `scripts/verify_hot_switch.py --live --legacy-upgrade --source-root /path/to/original/repo` 完成[真实模型验证](artifacts/legacy-hot-switch-live-20261106.json)：Codex `0.167.0-alpha.3.2`，先经旧入口创建含工具历史的 OpenAI 聊天，首次升级加载一次配置后，同一聊天、同一引擎进程连续完成原生→qpool→原生，下一次提问直接生效；历史随机标记均正确。此旧聊天继续使用原订阅账号，未验证跨账号迁移。

旧版 `qpool-desktop` 提供方聊天不会被常驻入口自动迁移；其恢复流程会保留官方直连兼容入口，见下文。首次接管已打开的直连聊天、彻底断开都需要重新加载，不宣称任意现存连接能原地更换地址。回退到旧版 qpool 前应先彻底断开并重新加载 Codex。

隔离真实验证脚本：`python scripts/verify_hot_switch.py --live --source-root /path/to/original/repo`。它复制现有订阅访问凭据到忽略目录、去掉刷新令牌，仅创建合成聊天和测试文件；通过真实热切换接口验证两个方向及工具历史，保持每个聊天的进程、ID和配置不变。不会启用 API 计费，也不安装真实 LaunchAgent；结束后删除测试凭据副本。原生直通与 qpool 请求均写入会话审计，原生行的 `entry_mode` 为 `native`。

2026-11-06 的[真实往返验证记录](artifacts/hot-switch-live-20261106.json)包含九个阶段，两个方向都经过工具执行及重复切换；并非只检查配置或按钮状态。 全量回归 194 项通过，旧恢复原有失败已修复；独立复核未发现剩余阻断项。

### 旧版 Codex 桌面接入与恢复

macOS 桌面端读取用户级 `~/.codex/config.toml`（或明确设置的 `CODEX_HOME`），见[官方网关接入说明](https://learn.chatgpt.com/docs/enterprise/connect-to-a-gateway)。页面接入保留内置 `openai` 提供方身份，使用 `openai_base_url` 转发至本机 `/legacy/v1`，设置 `qpool-auto` 模型和绝对路径模型目录，不定义保留的 `model_providers.openai`。已有登录文件、MCP、插件和权限配置不会被改写。项目级配置会忽略提供方与转发地址，不能用它隔离桌面路由，见[官方配置说明](https://learn.chatgpt.com/docs/config-file/config-advanced)。原生账号统计属于当前登录账号，并非 qpool 多账号合计；GUI 功能仍需各自验证。

内置入口使用原生 OAuth 匹配已导入的订阅身份，配置不含 API Key 或订阅凭据；网关向上游发送选定账号的独立适配器凭据。新聊天首轮按方案分配执行账号，认证身份保持不变。已有助手／推理／工具历史的聊天不会因使用别名而自动换账号，原地切换需在页面明确安排。旧自定义提供方接入需要先在页面恢复官方配置，再重新接入；不会静默改写聊天提供方。用户级 LaunchAgent 维护后台启动；不能移动或删除仍被后台使用的项目及虚拟环境。

桌面接入是显式 opt-in。重启检查配置、端口和完整路由，恢复已保存的授权与会话绑定；相同方案重复启用保持授权。活动方案原位发布要等待在途请求结束，并保留当前轮次绑定；新用户轮次才使用新规则。手动停用或审计失败后不自动重新授权，不跨账号重放失败请求。

内置 `/legacy` 入口仅恢复本机账本确认且仍使用 qpool 别名的聊天模型，不能确认归属时保留配置并报错。

“恢复原 Codex 配置”恢复本次管理的默认模型设置、移除 LaunchAgent，撤销桌面本地凭据，保留后来添加的其他配置；若相关模型设置已被外部修改则拒绝覆盖并保留备份。备份为配置目录下 `native/codex-config.before-desktop.toml`，权限 0600。回退不停止可独立使用的 qpool CLI 入口；重启桌面应用生效。

当前 Codex `0.166.0-alpha.6` 禁止修改已有聊天的提供方 ID。恢复时若遇到明确的 `modelProviderMismatch`，保留旧提供方 ID，但将它改为官方 HTTPS 地址和原生 OAuth 认证，并提供显式选择该提供方的命令；新聊天默认使用 `openai`。控制台显示带目标 `CODEX_HOME`、已验证 Codex 路径及 `--no-daemon -c 'model_provider="qpool-desktop"' resume --all --include-non-interactive` 的命令，用于显式打开旧聊天。旧聊天 ID、历史、归档状态和已有官方模型保留，`qpool-auto` 等别名替换为接入前的官方模型。恢复记录保存为 `native/desktop-recovery.json`，历史备份保存在 `native/chat-recovery-*`。这不是将旧聊天无缝迁移到默认原生提供方，也不保证桌面默认列表直接打开旧聊天。

兼容入口使用**当前 Codex 原生登录账号**，不会继续使用旧 qpool 路由账号；跨账号的加密推理历史能否续推尚未验证。旧聊天被占用、其他协议错误、恢复记录写入或后台停止失败时，恢复报错并保留配置与授权以便重试。协议恢复可能已经修改部分聊天的模型，失败不代表这些聊天仍能从旧网关继续；错误提示会要求先重试完成恢复，历史备份保留恢复前的模型信息。隔离真实协议测试经过恢复后的最终配置，验证新聊天原生默认入口、旧 ID、历史、隐藏审批模型和归档状态，以及收尾失败后再次恢复；未发起模型推理。

### 官方 API 和更多订阅账号

在“接入账号”中选择 **接入 OpenAI API Key**，填写已有 Key 与账号名称。表单显示保存目录，勾选保存与计费说明后点击“验证 Key 并接入”。只向固定的 `https://api.openai.com/v1/models` 验证目录，不支持填写其他服务地址，也不会因接入而发起推理。Key 写入 `native/api-keys/` 的 0600 文件；配置中仅存引用和指纹，浏览器提交后立即清空输入，状态接口不回传 Key。

路由和决策模型均可选择这个 API 账号。使用前需在方案勾选 **允许 API 计费**，页面的决策测试也检查该许可。混合方案优先订阅账号，再考虑明确加入的 API 模型；同会话仍固定账号，不会失败后跨账号重放。API Key 的模型列表不能证明余额或推理权限，页面显示“余额未知”，不伪造订阅额度、零费用或余额保证。推理实际用量见会话记录，价格与账单以 OpenAI Platform 为准。

方案支持 **Plus（优先使用 5 小时窗口）→ Pro → API**，Plus 同时受周额度约束。新会话自动选择，用户不需切换 API 方案；订阅额度未知或刷新失败时，不将它视作耗尽而进入付费 API。已绑定的会话保持执行账号，工具续轮固定模型，不失败后重放；原生历史聊天可明确安排订阅迁移。当前生产仍关闭，本轮隔离测试没有启用 API 推理。

另一个 Plus／Pro 账号通过“登录另一个账号”完成官方登录，再选择发现的账号接入。每个账号有独立登录目录和执行适配器；需要将第二账号模型加入方案的两组，才会参与该方案的选择。

### 模型目录同步

账号页支持全量或单账号同步，服务启动 30 秒后自动同步，此后约每 5 分钟同步一次。订阅适配器恢复远程目录更新，不再使用 `-local-model` 固定嵌入目录。qpool 还会读取 CPA 项目维护的[公开目录](https://raw.githubusercontent.com/router-for-me/models/refs/heads/main/models.json)，按真实登录套餐选择对应段，并等待本地适配器加载对应模型；公开源失败、结构不完整或本地尚未加载时保留上次列表。这个目录是适配器数据源，不是 OpenAI 对账号权限的保证。

API 账号使用官方 `/v1/models`。原 Codex 可选集合还需匹配本机最新 `models_cache.json` 的可见模型能力信息；隐藏模型、缺少能力信息及上游未提供的模型，在账号卡片展开查看原因。已确认移除的模型保留渠道 ID 但标为不可选，旧方案需调整；未改变的模型不会因同步中补充默认字段而打断原会话。若本机能力目录仍旧，请先启动原 Codex 更新本机目录，再点击同步。

默认配置和额度库分别为 `~/.qpool/pools.json`、`~/.qpool/qpool.db`。本任务使用独立目录试用：

```bash
QPOOL_CONFIG="$PWD/.qpool/console/pools.json" \
QPOOL_DB="$PWD/.qpool/console/ledger.db" \
python3 -m qp web --port 8765
```

## 路由和执行规则

- **模型判断**：直接复用 HiRoute `smart_saving` 的问题构建、难度标准、概率校验和分组函数。固定来源为上游提交 `52d2b9b0f131ef423930f8c2834683b27696ad2d`，原代码及 Apache-2.0 许可见 `qp/_vendor/hiroute/`。当前任务先由页面选择的模型真实评分，简单概率达到门槛（默认 0.8）才使用常规组。订阅模型通过 Responses 调用，自评概率并不等同于原 Jev 专用模型的校准质量；准确率仍需真实任务集评估。
- **决策上下文**：发送当前任务及最多六轮可见的用户／助手文字，排除 system/developer 提示、工具结果、图片和隐含状态；截断或缺失会标记上下文不完整。当前任务最多 16,000 UTF-8 字节，总上下文上限 32 KiB。决策模型不开工具，不经过执行网关，避免递归判断。
- **判断失败**：输出无效、超时、并发忙或不可用时明确回退主力组，仍受账号、权限和额度约束，不使用关键词伪装模型判断。总判断预算含排队，页面可配 1–30 秒；最多两个并发判断，同账号串行。判断会额外占用订阅额度和延迟；超时后已到上游的调用可能仍消耗额度，其用量标记未知，不伪造为零。
- **外部 HiRoute 服务**：在页面选择该来源并填写 `/v1/decisions` 地址，可选填服务进程中的 `QPOOL_DECIDER_*` 认证环境变量名称，不在页面输入密钥。远程服务必须使用 HTTPS；本机允许 HTTP。按 HiRoute 的五字段协议发送任务和上下文，采用服务返回的分组，概率门槛由服务管理。没有服务地址时直接使用已接入订阅模型即可。
- **本地规则**：明确的简短翻译、摘要等文字任务走常规组；编程、工具操作、复杂或不确定任务走主力组。常规任务可回退主力组。这是保守的规则基线，不是 HiRoute 决策模型，未验证分类准确率或成本节省。
- **会话绑定**：每个新的用户轮次可重新选模型；真正的工具续轮和上下文压缩沿用该轮绑定。同一会话保持账号不变，避免跨账号迁移推理状态。自动路由两组至少要有一个共同账号；当前账号无法执行新轮要求时，应新建会话重新选账号。
- **订阅额度**：每次上游请求开始前重新检查身份、渠道及额度，包括等待同账号请求完成后。过期读数触发同步，未知或耗尽就拒绝执行。按接口实际窗口秒数区分 5 小时和周额度，不能假定 primary 一定是 5 小时。额度是观察值，不是预占或保证。API 路径检查独立计费许可和凭据，余额由上游判定。
- **账号隔离**：每个账号对应一个 qpool 私有 CPA 进程和仅含该账号的认证目录；关闭 CPA 的账号、模型自动切换及额外重试。不修改用户已有 CPA 服务、配置或全局策略。
- **不重放**：上游失败、流中断或工具续轮找不到绑定时不会改用另一个账号重试。仅使用 CLI 时，服务重启后需要重新启用入口；桌面接入后会恢复已授权且未变化的活动路由。重新启用/修订路由后也必须新建会话；服务重启后同样需新建会话，历史请求存在而内存绑定已丢失的会话会被明确拒绝；不恢复未知的执行中状态。`previous_response_id` 模式不支持，原生 Codex 使用完整上下文。
- **容量边界**：全局最多 4 个模型请求，同账号串行；请求体上限 8 MiB、流式响应上限 32 MiB、上游空闲超时 180 秒。未进行压力测试。多个配置文件如果共用同一目录，也只能启动一个原生网关。

原有 `quota run --auto-model/--group/--tier` CLI 保留。旧 CLI 渠道仍按原账户池规则运行，新增 `native` 渠道仅供原生网关使用，不会被旧 CLI 执行器误执行。旧路由保留原模式，需要在页面手动改为模型判断并保存启用。会话库只新增决策表和可空的关联列，旧请求记录继续可读；若回退旧版，请先停用入口并将路由切回固定／本地规则，旧版不支持新增的模型判断模式。

## 凭据、历史和停用

本地控制台仅监听 `127.0.0.1`，管理 API 校验 Host、Origin 和专用请求头。原生网关另需随机 Bearer 令牌（CLI）或独立桌面本地令牌；该令牌存于当前用户可读写的入口文件，不返回给浏览器，不放在启动命令参数里。

账号配置只存登录文件引用和身份绑定。适配器临时目录存访问令牌，**不复制或轮换原 Codex 的刷新令牌**；访问凭据过期时在原 Codex 重新登录，或通过界面使用独立登录并重新关联。用户仍在官方登录页完成密码和验证，qpool 不接收密码。

运行材料位于配置目录下的 `native/`：路由方案、能力目录、入口文件、会话库和临时账号适配器。敏感文件权限为 0600、可执行入口为 0700；适配器关闭时删除临时认证和日志文件。强制终止无法保证清理在途进程，需检查残留进程后再启动。请求记录写入失败时自动停用入口，避免继续产生无法记录的请求。

点击“停用入口”立即撤销新请求权限，已发到上游的请求可能继续完成。关闭控制台时等待在途请求结束并关闭适配器。未接入桌面端时，原 Codex 主配置不变。接入桌面端会同步改变普通 `codex` 的默认模型提供方；在页面点击“恢复原 Codex 配置”并重启客户端可还原。会话文件仍在原 home 中，但原生 `resume` 默认列表可能按提供方筛选；本版不保证跨提供方接续全部历史会话。
