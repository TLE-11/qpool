# Codex 同聊天模型同步入口

本分支增加可选的 App Server 控制代理。在新用户轮次进入 Codex 前完成路由，将真实模型和推理档位交给 Codex；HTTP 网关执行同一份已绑定计划。切回原生时恢复用户选择的原生模型，不需要把所有模型统一限制到最小窗口。

## 启用与恢复

1. 启动本分支的 qpool 控制台，启用已配置的路由。在 Codex 中保留真实模型选择，例如 Sol。
2. 在 **Agent 接入** 中接入常驻入口，再点击 **生成模型同步入口**。
3. 保存页面显示的启动命令，退出 ChatGPT/Codex 桌面后运行。启动器会拒绝在已有桌面运行时强行启动或终止它。
4. 打开原来的 OpenAI 聊天。在控制台切换 **使用原生 / 使用 qpool**；当前回复保持原模型，下一次正常提问使用新模式。
5. 之后通过生成的入口启动桌面。直接从原应用图标启动不会加载控制代理，仍受旧 HTTP 入口的模型能力兼容检查约束。

启动器只为它启动的应用设置 `CODEX_CLI_PATH`，没有修改系统环境或替换应用二进制。首次连接控制代理需重新启动桌面；聊天内切换无需重新启动。

彻底恢复时，在控制台选择 **彻底断开**，退出桌面后从原应用图标启动。原配置沿用现有备份恢复规则。恢复后即使继续使用生成的包装器，它也直接执行原生 Codex。

## 行为与边界

- Codex 原生提供方保持 `openai`，原聊天 ID 和模型可见历史保持不变。
- `turn/start` 的模型、推理档位及 Plan 模式中的对应设置一起更新。权限、审批、工具执行和事件流仍由 Codex 管理；审批模型保持原生账号。
- 路由只计算一次，生成不含提示词的持久化计划。HTTP 请求须匹配计划的聊天、登录身份、实际模型、轮次及路由版本；失败不会自动跨账号重放。
- 切到小窗口模型前，Codex 如先用旧模型压缩，则保留旧执行账号和模式完成压缩，再使用新模型生成。该压缩可能丢失历史细节；没有统一降低原生模型窗口。
- 原生模型与推理档位偏好独立保存。qpool 的自动模型选择不会覆盖切回原生时应恢复的偏好。
- 路由分类只接收有界的最近文本视图，长文本会截断并标记不完整；实际发给 Codex 的输入和完整模型历史不经过这项截断。
- 队列开始路径已接入预选和提交防重。请求已被 Codex 接受后，清理失败不会伪装成生成失败；提交结果未知时不自动重放。
- **本机 `0.167.0-alpha.3.2` 的真实排队验收受阻**：不经过 qpool 的隔离原生 App Server，`thread/queue/add` 返回 ID 后，`thread/queue/list` 立即为空，`thread/queue/start` 返回 not found；legacy 和 paginated 存储均复现。队列代理的模拟回归通过，但不能宣称实际排队功能已通过。当前验收范围是回复结束后直接发送下一次提问。
- 本轮未启用用户主桌面入口，也未完成桌面 UI 的模型选择器显示验收。协议和真实推理链路已验证；多代理内部自行创建的新聊天不包含在本轮真实验收中。

## 2026-11-08 验证报告

环境：macOS，安装版 Codex `0.167.0-alpha.3.2`，现有订阅登录的隔离副本，真实 `gpt-6.1-sol` 与 `gpt-6-astra`。测试未使用付费 API；此次模型切换保持同一个订阅账号，跨账号迁移不是本次真实测试的结论。

### 1. 双向切换与工具调用：通过

分别以原生和 qpool 创建聊天，执行原生 → qpool → 原生、qpool → 原生 → qpool，累计 9 个轮次。每个聊天的控制代理进程保持不变，聊天 ID 保持不变，历史文件标记均正确回忆。首次轮次实际调用读取文件工具。Codex 的 `thread/read.model` 与请求记录的实际执行模型一致，验证使用与桌面一致的 `features.code_mode_host=true`。

### 2. 旧聊天升级与跨窗口压缩：通过

先经旧 `/legacy/v1` 入口创建持久聊天并实际读文件，再一次性加载控制代理，恢复原聊天。升级后 3 轮使用同一进程和聊天：Sol 原生 → Astra qpool → Sol 原生。

为了以有限额度触发边界，仅在隔离目录将 Astra 的模型目录窗口设为 32k，并注入测试填充。真实 Codex 在切换时产生两次 `contextCompaction`：先由原生 Sol 处理旧历史，随后 Astra 处理新窗口并回答。压缩后及切回 Sol 后均能回忆原标记。这证明缩小窗口的压缩路径，不能据此推导已经压测了完整 272k/500k 极限。

### 3. 自动化回归与独立审查

全仓 264 项回归通过（136.681 秒），覆盖旧入口兼容、模式/轮次绑定、原生偏好、路由版本竞态、旧执行身份快照、长输入投影、子进程退出、排队提交防重。独立审查发现的问题均已修复并补回归；真实队列受阻单列，未算通过。JavaScript 语法检查及 `git diff --check` 通过。

脱敏的真实验证结果见 [control-routing-live-20261108.json](artifacts/control-routing-live-20261108.json)。原配置及原登录文件的哈希保持不变，测试副本中的登录凭证已删除。

复验命令（`--source-root` 指向已接入订阅的仓库，运行时只复制到隔离目录）：

```bash
python -m unittest discover -s tests -q
python scripts/verify_hot_switch.py --live --control --source-root /path/to/qpool
python scripts/verify_hot_switch.py --live --legacy-upgrade --control --control-compact --source-root /path/to/qpool
```

`--control-queued` 是额外的原生队列诊断场景；在上述安装版本上未通过，不应作为启用普通轮次切换的操作步骤。
